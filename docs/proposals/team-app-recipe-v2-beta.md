## 1. 한 줄 제안

**기존 레시피 추천은 그대로 두고, "새 추천(베타)"을 켜고 끌 수 있는 기능으로 옆에 붙여 써 보자**는 제안입니다. 써 본 결과를 보고 정식으로 바꿀지, 일부만 가져갈지, 접을지는 팀이 함께 정합니다.

## 2. 배경

- 팀 앱의 레시피 기능은 팀이 함께 만든 구조(Node 서버 + Supabase, 화면별 규칙)로 잘 동작하고 있습니다. 10월 18일에는 이 저장소의 레시피·재료 지식을 스냅샷으로 가져가 "만들 수 있는 레시피" 판정에 쓰고 있습니다(`docs/ontol-recipe-integration.md`).
- 팀 저장소에 영향을 주지 않으려고, 추천 로직 실험은 별도 저장소에서 진행했습니다.
- 팀은 Jev를 두 번 쓰지 않기로 했습니다. 이 제안은 그 결정을 존중하면서, 이번에는 **같은 평가 세트로 잰 근거**를 가지고 다시 검토해 보자는 것입니다.
  - 10-02 식단 선택: 차이가 작고 잴 기준이 없었음
  - #116 취향 추천: 가상 취향 5개에서 규칙과 최상위가 같았음

## 3. 베타가 사용자에게 주는 것

| 기능 | 지금 앱 | 새 추천(베타) |
|---|---|---|
| 못 먹는 것 | 원료·분류 제외 8개(우유·달걀·대두·밀·새우·생선·육류·버섯) | **알레르기 27그룹**(법정 표시 대상 등, 들어 있을 수도 있는 것까지 제외) + **절대 안 먹는 재료**(확실히 든 것만 제외) |
| 매운맛 | 없음 | **매운맛 정도 0~5**: 넘는 레시피 제외, 맛 정보가 없는 레시피는 고추류 재료가 없으면 맵지 않다고 판단 |
| 취향 반영 | 카드에 추천 강도 표시(순서는 그대로) | 좋아하는·싫어하는 재료, 음식 종류, 요리 실력을 **순위에 반영** |
| 랜덤 | 조건 통과 레시피 중 완전 무작위 | 무작위 40개 중 취향에 맞는 것 |
| 내 재료로 | 바로 가능 / 양념만 확인 / 1~2개 부족 / 재료 더 필요 | 지금 바로 / 조금만 사면(1~2개 부족), 대체재 인정 |
| 요리 찾기 | 이름·재료 검색 + AI가 3개 골라 설명 | 요리명이나 느낌("오늘은 얼큰한 국물이 끌려", "간단한 아침")으로 찾기 |
| 추천 이유 | 일치 재료, 추천 강도 | 항목별 점수(요청·맛·재료 취향·음식 종류·실력·가진 재료) |

## 4. 근거: 같은 평가 세트로 잰 결과

평가 세트는 44개 요청입니다(기존 기준 시나리오 14 · 테스트 페르소나 20 · 요리 문장 10). 같은 세트를 규칙 순위와 Jev 순위로 각각 돌렸습니다(2026-10-19, jev-1.14.0, 상세 `docs/review/v2_eval.md`).

| 지표 | 규칙 순위 | Jev 순위 |
|---|---|---|
| 안전 위반(엔진과 별도로 다시 판정, 반드시 0) | 0 | 0 |
| 결과 없음 비율 | 0.07 | 0.00 |
| 좋아하는 재료 적중(상위 5) | 0.44 | 0.59 |
| 좋아하는 음식 종류 비율 | 0.41 | 0.47 |
| 싫어하는 음식 종류 비율(낮을수록 좋음) | 0.08 | 0.04 |
| 서로 다른 주재료 수(상위 10) | 13.5 | 20.8 |
| 평균 응답 시간 | 27ms | 353ms |
| 요청당 Jev 입력 토큰 | 0 | 약 3만 |

한계도 함께 적습니다.

- "좋아하는 재료 적중" 등은 **자동으로 잰 대리 지표**이고, 실제 사용자 만족을 잰 것은 아닙니다. 그래서 베타에서 실제 반응을 보자는 것입니다.
- 골든셋 적중(0.54)은 두 방식이 같았습니다. 기대값이 예전 검수 레시피 50개 기준이라 1,522개 전체에서는 낮게 나옵니다.

## 5. 대가

- **속도**: 요청마다 Jev 판단 0.2~0.5초가 더해집니다. 애매한 문장은 약 1초입니다. Jev가 응답하지 않으면 규칙 순위로 바로 대체합니다.
- **비용**: 요청 한 번에 Jev 입력 약 3만 토큰입니다. 애매한 문장은 7만~13만 토큰입니다.
- **외부 전송**: 순위를 정하려고 TypeSafe(Jev)에 아래 정보를 보냅니다. #116에서 "계정 취향을 TypeSafe에 보내지 않는다"고 정했으므로, **이 부분은 팀의 명시적인 동의와 개인정보 고지 검토가 필요합니다.**
  - 보내는 것: 요리 실력, 매운맛 취향, 좋아하는·싫어하는 재료 이름, 음식 종류 선호, 요청 문장, 보유 재료 이름(먹을 수 있는 것만), 후보 레시피 요약
  - 보내지 않는 것: 알레르기, 절대 안 먹는 재료, 사용자 id, 레시피 id

## 6. 베타 방식: 팀 앱 변경을 최소로

| 항목 | 내용 |
|---|---|
| 기존 기능 | **그대로 유지.** 건강 정렬, 배달 메뉴 대안, 레시피별 좋아요·싫어요, 음식 종류 탭, 룰렛, AI 질문 모두 바뀌지 않음 |
| 팀 앱에 추가되는 것 | ① "새 추천(베타)" 토글 또는 탭 ② 서버 경로 1개(새 추천 서비스 호출) ③ 베타 화면에서만 쓰는 사용자 정보 입력(알레르기 그룹·절대 안 먹음·매운맛·음식 종류·요리 실력) |
| 추천 로직 위치 | 이 저장소의 엔진을 **별도 서비스**로 띄우고 팀 앱 서버가 호출. 로직이 한 곳에만 있어 팀 앱 코드에 판정 로직이 섞이지 않음 |
| 끄기 | 토글을 끄면 즉시 기존 추천만 남음. 접기로 하면 ①~③만 지우면 됨 |
| 회원 데이터 | 팀 앱 DB에만 저장. 새 추천 서비스는 요청 때 받은 정보로 계산만 하고 저장하지 않음(DB 없음) |

### 새 추천 서비스를 띄울 곳 (선택 필요)

| 선택지 | 장점 | 단점 |
|---|---|---|
| Render 서비스 추가(무료) | 비용 없음 | 15분 쉬면 잠들어 첫 요청이 30~60초 |
| Render 서비스 추가(유료 최소 플랜) | 항상 켜짐 | 월 비용 발생 |
| 팀이 쓰는 VPS에 함께 | 추가 비용 거의 없음 | VPS 관리 부담, 접근 권한 필요 |

서비스를 띄우기 전에 이 저장소에서 준비할 것이 있습니다.

- DB 없이 뜨는 v2 전용 실행 진입점
- API 키 인증
- 팀 앱 형식의 레시피 id 응답(`fs_1000` ↔ `foodsafety-1000`, `aehobak_bokkeum` ↔ `ontology-aehobak_bokkeum`)
- 서버 로그 기록

## 7. 진행 순서와 판단 기준

1. **합의**: 이 문서로 베타 진행, 외부 전송 범위, 서비스 위치를 정합니다.
2. **이 저장소 준비**: 6장의 서비스 준비 항목을 진행하고 배포합니다.
3. **팀 앱 베타 PR**: 브랜치에서 작업해 PR로 리뷰받습니다. 토글, 서버 경로, 베타용 입력 순서입니다. 기본값은 꺼짐입니다.
4. **베타 기간(예: 2주)**: 팀원과 일부 사용자가 기존·새 추천을 함께 써 봅니다. 보는 지표는 아래와 같습니다.
   - 새 추천을 켠 비율과 유지한 비율
   - 추천 레시피의 상세 열기·식단 저장·조리 기록 비율(기존 추천과 비교)
   - 알레르기 관련 문제 제보(0이어야 함)
   - Jev 실패율과 응답 시간
5. **결정**: 아래 셋 중 하나를 고릅니다.
   - (가) 정식 통합: 팀 앱 코드로 옮기고 기존 추천 로직 정리
   - (나) 일부만 채택: 예를 들어 알레르기 27그룹과 매운맛만
   - (다) 접기

정식 통합(가)을 고르면, 지금 앱에만 있는 기능의 처리를 그때 함께 정합니다. 대상은 건강 정렬, 배달 대안, 레시피별 반응, 음식 종류 필터, 버섯·육류 제외, 구매 예정 재료, 페이지, AI 설명 문장입니다.

- [ ] 베타 기간과 판단 지표(7장)

## 9. 안전에 대해

- 알레르기 판정에 Jev(AI)를 쓰지 않습니다. 제외는 규칙으로 먼저 끝내고, Jev는 제외를 통과한 레시피 안에서 순서만 정합니다. 제외된 레시피는 Jev가 어떤 답을 해도 다시 나오지 않습니다(테스트로 확인).
- 정체를 모르는 재료가 든 레시피는 알레르기가 있는 사용자에게 보여 주지 않습니다.
- 안전 테스트 일부를 소개합니다.
  - "새우 알레르기면 김치(새우젓 포함 가능)가 든 레시피 제외"
  - "고명·선택 재료라도 알레르기 재료면 제외"
  - "Jev가 목록 밖 레시피를 답해도 무시"
  - "Jev가 실패하면 규칙 순위로 대체"
  - "알레르기 정보는 외부로 보내지 않음"
- 알레르기 안전 테스트 181개는 제가 직접 실행해 통과를 확인했고, 전체 테스트 697개가 통과합니다.
