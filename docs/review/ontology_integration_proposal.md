> 작성: 2026-10-16. **제안 문서이며 구현하지 않았다.** 사람이 승인하면 통합 브랜치에서 단계별로 진행한다.
> 목표: 여러 브랜치에 흩어진 레시피(출처 4곳)와 재료·알레르기 지식을 **하나의 그래프(레시피 → 재료 → is_a·derived_from → 알레르기 그룹)**로 이어서 `/viz`에서 보는 것. 핵심은 git 병합보다 재료 정규화와 연결이다.
> 안전 규칙(CLAUDE.md)은 그대로다: 알레르기는 결정적 규칙으로만 판정, 미매칭 재료가 있는 레시피는 알레르기 사용자에게 제외, 새 데이터는 `status: draft`, `tests/allergy/` 무수정.

## 용어

- **엔진 시드(draft)로 넣는다**: `data/recipes/<id>.yaml` 형식(재료가 knowledge 정규 ID)으로 바꿔 로더(`load_recipes.py`)가 DB에 적재하게 한다. `status: draft`라서 `config/engine.yaml`의 `serve_draft_recipes: false`(기본값)에서는 **추천 결과에 나오지 않고**, 골든셋에도 영향이 없다. 사람이 검수해 `published`로 바꾸면 추천에 쓰인다. 그래프(`/graph?recipes=all`)에는 바로 보인다.
- **엔진 미적재(그래프 표시 전용)**: `data/recipes/`에 넣지 않아 DB·추천 엔진이 모르는 레시피다. 그래프를 만들 때만 같은 지식(별칭 색인, 컴파일된 알레르기 closure)으로 재료를 연결해 겹쳐 보여 준다. adhoc-1(외부 레시피 분석)과 같은 방식이다.

## 1. 통합 범위: 출처마다 다르게 넣는다

| 출처 | 추천 | 이유 |

| 기본·확장 100, 자취요리신 100 | 엔진 시드 그대로(published 50 + draft 150) | 이미 시드 형식, knowledge 자동 병합 |
| 살림팝 169 | **엔진 시드에 draft로 변환** | 요리권·시간·난이도·맛·도구가 모두 있어 시드 형식을 채울 수 있다. 자취요리신 변환(`convert_simplecooking.py`)과 같은 방식. 원본 YAML은 바꾸지 않는다 |
| 식품안전나라 1153 | **그래프 표시 전용(엔진 미적재)** | 요리권·조리시간·난이도·맛이 없어 로더가 거부한다(plan 5-3-1 4번). 억지로 채우면 추측값이 된다 |

- 그래프에서는 출처 구분 없이 레시피 → 재료 → 알레르기가 하나로 이어지고, 레시피 노드에 출처 색·필터를 둔다.
- 레시피 약 1,520개. viz-5 측정에서 1천 개 로딩이 3~5초였으므로 **첫 화면은 시드만, 출처는 토글**로 켠다. 통합 후 같은 측정을 다시 한다.

## 2. 미매칭: 세 단계로 처리

| 출처 | 미매칭 줄 | 미매칭 없는 레시피 |
| --- | --- | --- |
| 자취요리신 | 5.1% | 54/100 |
| 살림팝(병합 knowledge 기준 정확 일치) | 19.2%(재료명 198종) | 21/169 |
| 식품안전나라 | 28.9% | 82/1153 |

1. **확실한 별칭·표기 정리**: fs-3 보강안 A(별칭 60개) + 살림팝 표기(예: 케챱 → 케첩, 페페론치노, 전분가루 → 전분). 살림팝 재료명에 섞인 분량 표현("고추장 크게", "양파 작은거", "두꼬집 진간장")은 변환 단계 규칙으로 뗀다(원본 YAML 유지, 규칙은 변환 기록에 남김).
2. **새 재료 노드(draft)**: fs-3 보강안 B(71개) + 살림팝 빈출(코인육수 36회, 알룰로스 12, 다시다 11, 매실청 9, 스팸 7 등). 성분이 불확실하면 알레르기를 `possible`로 넓게, `confidence: low`.
3. **나머지는 미매칭 유지**: 1회 표기, 상표 제품(불닭소스·너구리·햇반 등), 모호어("파", "깨"). 그래프에 "연결 안 된 재료" 노드로 보이고 알레르기 사용자에게는 계속 제외된다.

- 예상: 식품안전나라 28.9% → 약 15.5%(fs-3 시뮬레이션), 살림팝은 한 자릿수 % 목표.
- **사람 확인 필수**: 별칭은 알레르기 판정을 직접 바꾼다(잘못 연결하면 걸려야 할 레시피가 통과). 에이전트가 별칭·새 재료 검수표를 만들고, 사람이 O/X 한 것만 반영한다.

## 3. 출처가 다른 같은 요리: 합치지 않고 화면에서만 묶는다

- 제목 정확 일치로 2개 이상 출처에 있는 요리 **17건**(시드·살림팝 8, 시드·식품안전나라 6, 시드·자취요리신 2, 식품안전나라·살림팝·자취요리신 1). 예: 제육볶음, 잡채, 알리오올리오, 순두부찌개.
- 같은 이름이라도 재료·분량이 달라 알레르기 결과가 다를 수 있으므로 **레시피는 각각 둔다**.
- 그래프를 만들 때 정규화한 제목으로 "같은 이름" 관계를 계산해 묶어 보여 준다(표시 전용, knowledge·시드 무변경).
- 비슷한 이름("소불고기"/"불고기")은 자동으로 묶지 않는다. 요리 유형 축(고도화 B5)이 생긴 뒤 검토.
