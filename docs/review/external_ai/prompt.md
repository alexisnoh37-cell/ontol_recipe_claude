# 외부 AI 검토 지시문 — 식재료·알레르기 연결 검토

> 사용법: 아래 "지시문" 블록 전체를 다른 생성형 AI(ChatGPT, Gemini 등)에 붙여넣고, 같은 폴더의 `data_bundle.md`를 첨부(또는 이어서 붙여넣기)합니다.
> 한 번에 다 못 받으면 `data_bundle.md`의 섹션 단위로 나눠 보내고, 마지막에 "이제 검토 시작"이라고 보냅니다.
> 외부 AI의 답은 참고 의견입니다. 알레르기 판정 근거로 그대로 반영하지 않고 사람이 검수표에서 확인한 뒤 `knowledge/`에 반영합니다(CLAUDE.md 안전 규칙).

---

## 지시문 (여기부터 복사)

당신은 한국 식품 알레르기 표시 기준과 한식 식재료에 밝은 검토자입니다. 레시피 추천 서비스의 **식재료 지식 데이터**에서 각 재료가 어떤 알레르기 그룹에 연결되는지가 맞는지 검토해 주세요. 데이터는 첨부한 `data_bundle.md`에 있습니다.

### 1. 서비스가 알레르기를 다루는 방식 (검토의 전제)

- 사용자가 알레르기 그룹을 고르면, 그 그룹에 연결된 재료가 **하나라도**(선택 재료·고명 포함) 들어간 레시피는 추천에서 **제외**합니다. 점수 감점이 아니라 제외입니다.
- 연결에는 확실성이 있습니다.
  - `definite`(확정): 거의 모든 제품·원물에 들어감
  - `possible`(포함 가능, 검수표에는 `(가능)`): 제품에 따라 들어갈 수 있음. **판정에서는 포함으로 간주해 제외**합니다.
- 따라서 이 서비스에서 가장 위험한 오류는 **알레르기 연결 누락**(있어야 할 연결이 없음)입니다. 연결이 과하면 추천이 줄어들 뿐이지만, 누락은 사용자에게 해가 됩니다.
- 알레르기 그룹은 23개 기본 그룹(법정 표시 대상 19개 + 자체 추가 4개)과 4개 묶음 그룹입니다. 법정 19개는 「식품 등의 표시·광고에 관한 법률 시행규칙」 별표 2 기준으로 사람이 확정했습니다. **그룹 목록 자체는 검토 대상이 아닙니다**(의견은 마지막 "기타 의견"에만 적어 주세요).

### 2. 데이터 구조

- 알레르기는 **원천 재료에만** 직접 적습니다(예: 새우에만 `shrimp`).
- 상속 규칙
  1. `derived_from`(파생 원천): 가공품은 원천 재료의 알레르기를 물려받습니다(예: 새우젓 ← 새우). 엣지에 `possible`이 붙으면 물려받은 알레르기도 `possible`.
  2. `is_a`(상위 개념): 하위 재료는 상위 재료의 알레르기를 물려받습니다(예: 차돌박이 is_a 쇠고기).
  3. 하위 개념이 있는 넓은 재료(예: 액젓)는 하위 재료들의 알레르기를 `possible`로 가집니다. 단 형제 재료로 퍼지지는 않습니다(새우가 해산물 하위라고 오징어 알레르기를 갖지 않음).
- `kind: concept`는 분류 전용 노드(예: 생선, 해산물)로 실제 재료로 쓰이지 않습니다.
- `aliases`(별칭)는 **같은 재료**로 취급됩니다. 알레르기 성분이 다를 수 있는 것을 별칭으로 묶으면 오류입니다.
- `confidence: low`와 `note`는 작성자가 확신이 없어 사람 검수가 필요하다고 표시한 항목입니다.

첨부 자료 구성
- **A. 검수표**: 상속까지 계산한 최종 결과. 열 "걸리는 알레르기(상속 포함)"가 실제 판정에 쓰이는 값입니다. **검토의 주 대상입니다.**
- **B. allergens.yaml**: 알레르기 그룹 정의
- **C. ingredients/*.yaml**: 원본(별칭 포함). 별칭 검토와 원인 추적에 사용

### 3. 검토해 줄 것 (우선순위 순)

1. **누락된 알레르기 연결**: 재료(특히 가공품·양념·소스·면·가공식품)에 있어야 할 알레르기 그룹이 빠졌는지. 예: 시판 제품에 흔히 들어가는 밀·대두·우유·계란·아황산류 등.
2. **잘못된 그룹 배정**: 다른 그룹에 연결된 경우. 예: 어떤 생선이 `mackerel`(고등어)인지 `other_fish`(기타 생선)인지, 어떤 해산물이 `squid`/`other_cephalopods`/`shellfish`/`crab`/`shrimp` 중 어디인지.
3. **확실성 오류**: `definite`여야 하는데 `possible`이거나 그 반대인 것.
4. **위험한 별칭**: 별칭으로 묶여 있지만 알레르기 성분이 다를 수 있는 것(예: 원료가 다른 제품, 첨가물 처리 여부가 다른 제품).
5. **잘못된 파생·상위 관계**: `derived_from`/`is_a`가 사실과 달라 상속이 틀어진 것.
6. **`confidence: low` 항목의 메모에 대한 답**: 메모에 "확인 필요", "검수"라고 적힌 질문에 대해 아는 범위에서 답해 주세요.
7. 불필요하게 과한 연결(우선순위 낮음): 사실상 들어가지 않는데 연결된 것.

### 4. 답변 규칙

- **추측과 사실을 구분해 주세요.** 각 지적에 근거 유형을 적습니다: `법령/공식기준`, `일반적 제품 성분`, `식품학 일반지식`, `추정`. 확실하지 않으면 `추정`이라고 쓰고 확신도를 낮게 주세요. 모르는 것은 모른다고 적어 주세요.
- 근거로 출처(법령 조문, 공공기관 자료 등)를 댈 수 있으면 적되, **확인되지 않은 출처나 URL을 만들어내지 마세요.**
- 제품마다 다른 경우는 "definite로 바꾸라"보다 "possible 추가"를 제안해 주세요(서비스는 보수적으로 제외하는 쪽을 택합니다).
- 데이터 구조나 규칙 변경 제안이 아니라 **데이터 값**을 검토해 주세요. 구조 의견은 "기타 의견"에만 적습니다.
- 이상 없는 재료는 나열하지 마세요.

### 5. 출력 형식

아래 표 하나로 정리하고, 심각도 순(높음 → 낮음)으로 정렬해 주세요.

| # | 재료 id | 재료 이름 | 문제 유형 | 현재 값 | 제안 값 | 근거 | 근거 유형 | 확신도 | 심각도 |
|---|---|---|---|---|---|---|---|---|---|

- 문제 유형: `누락` / `잘못된 그룹` / `확실성` / `위험한 별칭` / `관계 오류` / `메모 답변` / `과한 연결`
- 확신도: `높음` / `중간` / `낮음`
- 심각도: `높음`(알레르기 사용자가 노출될 수 있음) / `중간` / `낮음`(추천이 줄어드는 정도)
- 제안 값은 `derived_from`, `allergens`, `aliases`, `is_a` 중 무엇을 어떻게 바꿀지 구체적으로(예: `derived_from에 {id: wheat_flour, certainty: possible} 추가`). 참조할 재료가 데이터에 없으면 "새 재료 필요: ○○"라고 적어 주세요.

표 뒤에 다음을 짧게 덧붙여 주세요.
- **요약**: 심각도 높음 건수와 가장 우려되는 3가지
- **확인하지 못한 것**: 정보가 부족해 판단을 보류한 재료
- **기타 의견**: 그룹 목록·구조에 대한 의견(있으면)

## 결과를 받은 뒤 (사람용 메모)

1. 외부 AI 답변을 `docs/review/external_ai/result_<AI이름>_<날짜>.md`로 저장합니다.
2. 여러 AI에게 받았다면 같은 지적이 겹치는 항목부터 봅니다.
3. 반영할 항목은 Claude Code에 "외부 검토 결과 중 #3, #7 반영해줘"처럼 지시합니다. 반영 시에도 확신이 낮은 항목은 `confidence: low`와 `note`를 붙이고 `status: draft`로 둡니다.
4. `data_bundle.md`는 생성 시점의 스냅샷입니다. `knowledge/`를 고친 뒤 다시 검토받으려면 번들을 새로 만듭니다.
