## D1. 서비스 대상

- 기본값: 개인용 프로토타입(본인과 가족만 사용). 로그인 없이 사용자 프로필을 여러 개 만들어 전환하는 방식.
- 외부 공개라면: 면책 문구, 개인정보 처리 방침(알레르기는 건강정보), 로그인이 추가로 필요하다.
- 결정: 기본값

## D2. 선택 재료에 알레르기 성분이 있을 때

- 대안: "이 재료는 빼고 조리하세요" 안내와 함께 추천한다. 이 경우 CLAUDE.md 안전 규칙도 함께 바꿔야 한다.
- 결정: 기본값

  - 원본과 변환 결과는 git에 올리지 않는다(재배포 방지, `data/external/`, `data/recipes_foodsafety/` gitignore).
  - 변환 결과는 `source: foodsafety`, `status: draft`, `confidence: low`, cuisine `미분류`, role `sub`. draft에 한해 cook_time_min을 비울 수 있다. 상세: docs/plan.md 5-3-1.
- 보완 3(2026-10-16, 사람 결정): 식품안전나라 원본(`data/external/foodsafety/raw/`)과 변환 결과(`data/recipes_foodsafety/`)를 git에 커밋한다. 보완 2의 "git에 올리지 않는다"를 대체한다.
  - 저장소가 공개(PUBLIC) 상태임을 확인하고, 공공누리 미표시·사전 협의 요구 조건도 안내받은 상태에서 내린 결정이다. 근거: 이 온톨로지는 백엔드 동작을 시각적으로 보여 주는 용도다.

  - 커밋에 API 인증키가 들어가지 않는다(`.env`만 사용, 원본 JSON에 키 없음 확인).
- 예외(2026-10-16, 사람 결정): 자취요리신 YouTube 데이터셋(`data/simplecooking_recipe_dataset/`) 100개는 설명란 원문(raw_text·조리 단계)을 유지한 채 `data/recipes/`에 draft로만 넣는다. `source`에 영상 URL을 남긴다. published로 바꾸기 전에 출처 이용 조건과 본문 표현을 다시 검토한다.

  - 살림팝 YouTube 데이터셋(`data/sallimpop_recipe_dataset/`) 169개에도 위 예외를 그대로 적용한다(원문 유지, draft, source는 영상 URL, published 전 재검토).

## D6. Jev로 레시피 속성 채우기 (오프라인 라벨링)

- 배경: 식품안전나라 레시피 1153개는 cuisine `미분류`, 조리시간·맛·난이도 없음, role 모두 `sub`라 적재되지 않는다. 사람이 모두 채우는 것이 병합의 가장 큰 병목이다. 추천 로직 논의(2026-10-17)에서 Jev(TypeSafe AI의 System One 결정 모델: 타입이 정해진 질문에 선택지·점수·예/아니오와 확신도만 돌려줌)를 런타임 추천(재정렬·문장 해석)에 쓰는 방안과 데이터를 채우는 데만 쓰는 방안을 비교했다.
- 결정(2026-10-17, 사람 승인): **Phase 2 범위 예외로, 오프라인 라벨링 도구에 한해** Jev를 쓴다. 런타임 추천 연동(재정렬, 문장 해석)은 하지 않는다(필요하면 progress.md "다음 단계 제안").
- 안전 경계(예외 없음)
  - `engine/`은 Jev를 호출하지 않는다. 추천은 기존 룰 엔진 그대로다(속도·재현성·breakdown 유지).
  - Jev는 재료 정규 ID 매핑과 알레르기 판정에 쓰지 않는다. 매핑이 알레르기 판정을 결정하므로 별칭 보강(fs-3)은 사람 검수로만 한다.
  - Jev가 채우는 것: 맛 6항목(0~5), 난이도(1~3), cuisine(vocab 4개, 맞는 것이 없으면 `미분류` 유지), 조리시간 구간, 재료 줄 role, 필수 조리기구. 새 레시피 필드는 만들지 않는다.
  - Jev가 채운 레시피는 `status: draft`를 유지하고, 확신도가 기준보다 낮은 값은 `confidence: low`로 검수표에 올린다. published 전환은 사람 검수 후에만 한다.
  - Jev에는 레시피 정보(제목, 재료 원문, 조리 단계)만 보낸다. 사용자 정보는 보내지 않는다.
- 인증키는 `.env`의 `JEV_API_KEY`. 응답 원본은 `data/external/jev/`(gitignore)에 저장해 같은 결과를 다시 쓸 수 있게 한다.
- 정확도 기준과 필드별 사용 여부는 검수된 published 레시피와 비교한 평가(jev-3) 후 사람이 정한다: 미정.
- 상세: docs/plan.md 부록 F.
- 이후 변경: D7(2026-10-18)이 "런타임 추천 연동은 하지 않는다"와 "`engine/`은 Jev를 호출하지 않는다"를 v2 범위에서 바꾼다. 라벨 결과를 레시피 YAML이 아닌 별도 파일에 둔다(D7). 배경의 "적재되지 않는다"는 ar-1(D3 이력) 이후 사실이 아니다(지금은 '모름'으로 적재).

## D7. 추천 v2: 3가지 추천 형태와 Jev 실행 중 재정렬

- 배경(2026-10-18, 사람 요청): 로컬 레시피·재료·알레르기 데이터를 그대로 쓰면서 ① 랜덤 ② 보유 재료로 조리 가능 ③ 요리명이나 "비슷한 느낌", 이렇게 세 가지 형태로 추천받고 싶다. 추천의 중심은 Jev, 알레르기와 먹기 싫은 재료는 추천에서 아예 뺀다.
- 결정(2026-10-18, 사람 승인)
  - **기존 로직은 바꾸지 않고 v2를 나란히 만든다**(bl-1 방침, 새 브랜치 `feature/recommend-v2`·새 PR). 기존 `engine/*.py`, `/recommend`·`/browse`, `tests/allergy/` 기존 파일, 레시피 YAML, `config/` 기존 키는 무변경. 새 코드는 `engine/v2/`(순수 Python)와 `integrations/jev/`.
  - Jev는 라벨링(D6)에 더해 **요청 처리 중 재정렬**에도 쓴다(Phase 2 범위 예외 확대). 사람이 A(데이터만)와 B(실행 중 재정렬)의 차이(응답 지연, 비용, 재현성, breakdown, 외부 전송)를 설명받고 B를 골랐다.
  - 추천 대상은 엔진의 레시피 전체(1,522개, ar-1). 형태 2는 "지금 바로 가능 / 1~2개만 사면 가능" 두 묶음(엄격 + 근접 분리).
  - Jev 라벨은 레시피 YAML에 쓰지 않고 `data/labels/jev/`에 따로 둔다. v2만 읽어 원본의 '모름' 값만 채운다(레시피 데이터 고정, bl-1).
- 안전 경계(예외 없음)
  - 순서는 항상 규칙 필터 → 후보 → Jev 재정렬. Jev는 필터를 통과한 목록 안에서 순서만 바꾼다. 목록 밖 id는 버리고, 레시피를 추가하거나 제외된 레시피를 되살리지 못한다.
  - 알레르기 판정은 기존 `UserConstraints` 그대로(possible·선택·고명·기본 양념 포함, 알레르기 사용자 + 미매칭 = 제외). Jev는 매핑·알레르기 판정에 쓰지 않는다(D6 유지).
  - Jev가 실패하거나 시간을 넘기면 규칙 순위로 돌아가고 note를 남긴다. 랜덤 형태는 Jev를 쓰지 않는다.
  - Jev에 보내는 사용자 정보: 요리 실력, 맛 선호, 질의 문장. 후보는 요약(제목·음식 종류·맛·주재료 이름)만 보낸다. **알레르기·건강 정보와 사용자·프로필 id는 보내지 않는다.**
  - 확신도가 기준 미만인 Jev 라벨은 쓰지 않는다('모름' 유지). 맛을 모르면 매운맛 한도 사용자에게 제외된다(ar-1 규칙).
  - 성능 기준(p95 200ms)은 "LLM 제외" 기준대로 재정렬을 끈 상태로 잰다. 켠 상태는 따로 보고한다.
- 보완(2026-10-18, 사람 지시): 사람이 Jev API 키를 주고 "제일 최신 Jev로 구축"하라고 했다. 키는 `.env`의 `TYPESAFE_API_KEY`(공식 SDK와 같은 이름, 커밋 안 함). 모델은 최신 릴리스 `jev-1.14.0`을 버전으로 고정한다(`jev-latest` 별칭은 안정판 1.13.0을 가리킴). 재정렬 요청(맛 선호·요리 실력·질의 문장·후보 요약: 제목·음식 종류·맛·주재료 이름)은 이 지시에 따라 실제로 보내기 시작했다.
- 미정: 식품안전나라 레시피 정보(제목·주재료 이름)를 외부 서비스로 보내는 것이 이용 조건(D3 보완 2·3)에 맞는지 최종 확인, 라벨 확신도 기준(jev-3 후), 재정렬 가중치(`jev_weight` 0.5)·확신도 하한(0.3)·top_n(30) 기본값의 적정성.
- 상세: docs/plan.md 부록 G.

## D8. v2의 절대 불선호는 확실한 포함(definite)만 제외

- 배경: 절대 불선호도 알레르기와 같은 `ingredient_contains`를 써서 "포함 가능(possible)"까지 제외한다. 예를 들어 닭가슴살 불선호면 닭고기·햄·카레가루 등 19개가 더 빠진다(data-3 측정, progress.md 다음 단계 제안 11).
- 결정(2026-10-18, 사람 승인): **v2에서는** 불선호를 definite 포함만 제외한다. possible은 제외하지 않고 trace note로만 남긴다. 알레르기는 그대로 possible도 제외한다.
- 사람에게 알린 것: 이 기준이면 승인된 `tests/allergy/test_hard_dislike.py`의 김치볶음밥(김치 → 새우젓 possible) 제외와 다르다. 사람은 테스트 변경까지 승인했다. 다만 v1을 바꾸지 않기로 했으므로(D7) **v1과 그 테스트는 그대로 두고**, v2 전용 테스트(`tests/allergy/test_v2_*`, 신규·승인 대상)에서 v2 동작을 검증한다.
- 대체재 안전성(대체 안내)은 v2에서도 possible 불선호를 피한다(보수적 유지).
